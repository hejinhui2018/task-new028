# EventContract 埋点迁移验收台

产品团队升级业务埋点协议、旧版 SDK 仍在运行期间，用这个工具在浏览器本地把
**v1 / v2 混合 SDK 事件**按用户旅程（开通试用 → 创建项目 → 首次发布）逐步重放，
由一台**状态化旅程执行器**给出每一步「接受 / 等待 / 阻断 / 失效」的结论，
以及对**会话关联、实验分组、转化归因**的具体影响。

它不是“校验 JSON 后排序”：乱序事件会进缓冲等待前置阶段、超时会失效；
重复事件按事件 ID 幂等丢弃；隐私事件在入口整条拦截；旧版适配缺字段时显式记
缺口而不伪造。

## 快速开始

```bash
npm install
npm run dev       # 本地开发
npm test          # 运行全部测试（Vitest + Testing Library）
npm run build     # 类型检查 + 生产构建到 dist/
npm run preview   # 预览生产构建
```

全程浏览器本地运行：无后端、无网络上报，状态只写入 `localStorage`。

## 界面与操作

- **顶部案例选择器**：7 个内置迁移案例（正常混合、归因缺口、乱序补齐、迟到失效、
  隐私阻断、版本边界、重复上报）。
- **工具栏**：单步（`Space`）、自动播放 / 暂停、速度调节、拖动进度条跳转到任意
  到达点、撤销 / 重做（`⌘Z` / `⌘⇧Z`）、重置（`R`）。
- **左栏·到达队列**：事件按此顺序“到达”，▲▼ 手动调整到达顺序；支持整体倒序、
  故障注入（重复 / 迟到 / PII 字段 / 跨会话副本 / 确定性洗牌）。
- **中栏·旅程轨道 + 判定日志**：三张阶段卡片随状态点亮；每步展示判定原因
  （改名、拆分、缺口、去重、缓冲、TTL 失效……）与对四条链路的影响徽章，
  以及真正流入下游的归一化负载（含转换轨迹）。
- **右栏·链路状态**：会话关联、实验分组、转化归因、首次发布转化的实时状态，
  以及“下游实际收到”的有序清单——隐私事件永不出现其中。
- **导入混合事件**：粘贴单个事件对象或数组的 JSON，结构错误逐条定位。
- **协议与迁移规则**：结构化查看 / JSON 编辑 v1、v2 契约（严格 vs 宽松模式）、
  rename / split / dropPii / gap 迁移规则、隐私禁采名单、旅程与等待窗口。

## 执行管线（`src/domain/executor.ts`）

每个到达事件依次经过：

1. **版本边界**：未知 `schemaVersion` 直接拒收；
2. **隐私拦截**：禁采事件整条阻断（不落缓冲、不产生下游记录），禁采字段入口剥离
   （不掩码、不伪哈希）；归一化前还有第二道防线兜底；
3. **幂等去重**：同一用户下同一事件 ID 再次到达即丢弃（重复不二次计转化）；
4. **版本适配**：v1 事件按迁移契约 rename / split / dropPii；v2 必填而 v1 无来源
   的字段登记为 **gap，不伪造默认值**，因此必填缺失会真实阻断；旧版遗留字段
   剥离告警（严格性只约束原生 v2 生产方）；
5. **契约校验**：必填、类型、契约外字段（v2 严格阻断 / v1 宽松告警）；
6. **旅程乱序缓冲**：事件必须落在“下一个未完成阶段”；前置缺失则缓冲等待
   （`maxWaitMs` 窗口），前置到达后按正确顺序级联释放；超时失效；流结束封口后
   仍未成链的缓冲项永久失效；
7. **链路更新**：会话 ID 一致性（跨会话 → mismatch）、experiment_id+variant
   完整分组（只有 variant → variant-only 降级）、utm_source 归因，发布到达时
   结合归因状态给出 attributed / unattributed 转化结论。

结论是执行器状态推演的结果：同一输入任意次重放逐字节一致（确定性测试覆盖）。

## 测试

`src/domain/executor.test.ts` 覆盖题目要求的五类场景：

- **版本边界**：未知版本拒收、无迁移映射拒收、v2 严格模式契约外字段阻断、v1 宽松告警；
- **重复乱序**：同 ID 幂等、窗口内缓冲释放且下游顺序修正、窗口外 TTL 失效、完全倒序；
- **旅程关联**：改名 + 拆分保归因、gap 不伪造导致阻断、variant-only 降级、跨会话 mismatch；
- **隐私阻断**：禁采事件不进下游/缓冲、禁采字段剥离、乱序场景下隐私事件也不被悄悄释放；
- **重复重放**：同输入多次结果一致、重置再跑一致、重复 + 乱序叠加仍只计一次。

另有故障注入纯函数、导入解析、状态层（撤销/重做/跳转/localStorage 恢复）和
App 冒烟测试，共 37 个。
